# NailsBot Mini App

Готовый каркас Telegram Mini App для записи на ногти и администрирования салона.

## Локальный запуск

```powershell
npm install
Copy-Item .env.example .env
npm run dev
```

Для локального предпросмотра откройте `http://localhost:3000/?demo=1`. Режим `demo` показывает админку только в development и не должен использоваться в production.

## Подключение Telegram

В `.env` укажите:

```env
TELEGRAM_BOT_TOKEN=полный_токен_бота
TELEGRAM_ADMIN_CHAT_ID=1509034539
APP_URL=https://ваш-публичный-домен.example
ADMIN_IDS=1509034539
```

`APP_URL` обязан быть публичным HTTPS-адресом. `localhost` доступен только на компьютере разработчика и не открывается у Telegram как Mini App. После запуска бот показывает кнопку «Открыть запись» по команде `/start`, а администратор может открыть панель по `/admin`.

`TELEGRAM_ADMIN_CHAT_ID` — чат, куда отправляются уведомления о новых записях. Для личного чата администратора обычно используется его Telegram user ID. Токен и ID не должны попадать в исходный код или Git. Для обратной совместимости сервер также понимает старую переменную `BOT_TOKEN`, но в новых окружениях используйте `TELEGRAM_BOT_TOKEN`.

## Что уже есть

- запись клиента на услугу, дату и свободное время;
- уведомление администратора о новой записи после сохранения в `data/store.json`;
- защита от повторной отправки уведомления для одной записи;
- запись статуса отправки (`sent` / `failed`) и ручной повтор через `POST /api/admin/bookings/:id/notify`;
- подтверждение и отмена записей из админки;
- добавление услуг и слотов без редактирования кода;
- проверка Telegram `initData` на сервере;
- чёрный интерфейс с красными действиями и hero-изображением маникюра.

## Проверка уведомлений локально

1. Скопируйте `.env.example` в `.env` и задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_CHAT_ID`.
2. Убедитесь, что администратор хотя бы один раз открыл чат с ботом и нажал `/start` — Telegram не разрешает боту первым писать пользователю.
3. Запустите `npm run dev` и создайте запись через `http://localhost:3000/?demo=1`.
4. Проверьте сообщение в чате администратора. В `data/store.json` у записи появится `adminNotification.status: "sent"`.
5. Для проверки повторной отправки вызовите `POST /api/admin/bookings/:id/notify` с авторизацией администратора. Уже отправленная запись будет пропущена.

Если Telegram недоступен, `POST /api/bookings` всё равно вернёт успешное подтверждение и сохранит запись. В `data/store.json` будет `adminNotification.status: "failed"` с числом попыток и текстом ошибки; после восстановления Telegram отправку можно повторить через тот же endpoint.

Для production замените JSON-хранилище на базу данных и запустите приложение на хостинге с HTTPS.

## Деплой на Render

В репозитории есть готовый `render.yaml`. После подключения GitHub-репозитория в Render можно выбрать Blueprint и применить его настройки. Команды уже указаны: `npm install` и `npm start`; секретные переменные Render попросит заполнить вручную.

Для текущего JSON-хранилища нужен постоянный диск Render, иначе данные в `data/store.json` могут сбрасываться после пересборки. В качестве альтернативы перенесите записи в PostgreSQL перед запуском для реальных клиентов.
